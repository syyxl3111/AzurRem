# AzurRem 远程访问方案

> 目标：App 填一个 URL + 密码，**公网和内网都能操控 + 读数据**，行为对齐网页端。
> 状态：**已实现并实测通过**（2026-09-12）。落地形态是下面的「§A 已实施」，
> 原先列的路 A / 路 B / 路 C 比较保留在后面，用来说明为什么最后选了网关。

---

## §A 已实施：网关（路 C）

### 最终形态

```
                     ┌──────────── AzurRem 网关（就是升级后的数据桥 exe）────────┐
浏览器 ── GET /    ──→│ 极简状态页：「已连接 AzurPilot · 请在 App 上查看」        │
                     │（唯一不鉴权的出口；能区分 AP 没起来 / 密码不对）          │
App ──── /mcp/*    ──→│ 验 App 的密码 → 注入 AzurPilot 的密码 → 转发 :25548      │
App ──── /api/…    ──→│ 只放行 ap_timeline 与 cl1_stats 两个，同样注入密码       │
App ──── 9 条桥接口 ─→│ 自己读本地库（azurstats_local.db / cl1_data.db / CSV…） │
                     └──────────────────────────────────────────────────────────┘
                                      ↑ 绑 0.0.0.0:25550（内网）
                                      ↑ cloudflared 隧道（公网）
```

**AzurPilot 退到网关后面**：不再直接对公网，原来 `/api/ap_timeline` 匿名可读的口子也一并堵上。

### App 侧：一个地址 + 一个密码

| 网络 | 服务器地址 | ~~数据桥地址~~（1.0.4 起已移除） | 密码 |
|---|---|---|---|
| 内网 | `http://192.168.x.x:25550` | **留空** | 网关密码 |
| 公网 | `https://example.com` | **留空** | 网关密码 |

留空能成立，是因为 `Settings.effectiveBridgeUrl` 的推导规则改成了：
**端口是 25548（直连 AP）→ 换成 `host:25550`；否则（走网关）→ 用服务器地址本身。**
两种部署自动区分，老的直连方式不受影响。

### 两把钥匙，刻意分开

| 密钥 | 谁知道 | 用途 |
|---|---|---|
| **网关密码** | 用户 / App | 公网入口的钥匙。首次运行自动生成 32 位，写在 exe 旁边 `azurrem-gateway.key`，窗口里可选中复制 |
| **AzurPilot 密码** | 只有网关 | 服务端最后一道门。网关从 `config/deploy.yaml` 读，**始终不出电脑**，不用填进手机 |

网关密码**不写进日志**（`AzurRemBridge.log` 是 issue 模板里会让人贴出来的东西）。

### 安全边界

- **反代白名单**，不是通配。AzurPilot 上还挂着 `/api/launcher/startup`（能拉起进程）、
  `/api/import_legacy_upload`（能传文件）、`/ws/live_control`（**真能点屏幕**）——
  做通用反代等于把它们一起搬上公网。只放行 `/mcp/*` + 两个只读统计接口。
- 网关自己**没有任何写接口**：9 条桥路由全是只读，写操作一律走 `/mcp/*` 转给 AzurPilot。
- 常数时间比较密码（`hmac.compare_digest`），避免用响应时间逐位试出来。
- 删掉了原来的 `Access-Control-Allow-Origin: *`。

### 实测结果（2026-09-12）

| 测试 | 结果 |
|---|---|
| `bridge/gui_test.py`（挂件窗口） | **81 / 81** |
| `bridge/gateway_test.py`（网关，含 MCP 反代端到端） | **29 / 29** |
| 模拟器内网：`http://10.0.2.2:25550` + 网关密码 | 操控 + Tier 1 + **Tier 2 全部** |
| 模拟器公网：`https://example.com` + 网关密码 | 同上 |

### 实施中抓到的三个真问题（都靠测试，不是靠看）

1. **MCP 的 POST 也要凭据。** 直连 AzurPilot 时只有 `/mcp/sse` 验密码（之后靠
   `session_id` 认人），但**网关对自己的每个出口都验**。少了这一条，SSE 握得上、
   紧接着 `initialize` 就 401 —— 表现是"连上了但用不了"，比连不上更难查。
   App 的 `McpSession.post()` 和 `httpGet()` 都补上了。
2. **桥接口也要凭据。** 早先 `httpGet` 有个 `withAuth` 开关，刻意不给桥开
   （怕把密码发给用户随手填的地址）。网关模式下这个判断是错的 —— 表现是
   "资源趋势那格写着 Failed to connect to ...:25549"，看着像端口不通，实际是没带钥匙。
3. **挂件窗口的尺寸 bug。** `_move_to_default_position()` 写死用 `COMPACT`，
   归位时把刚按内容算好的高度又压回去。加了一行控件之后内容就顶出窗口了。
   改成"只挪位置、不动尺寸"。

> 另外还踩了两次同一个 Kotlin 坑：**块注释里写「斜杠 + 星号」会吞掉整个文件**
> （编译器只在文件末尾报 `Unclosed comment`）。已在 `gateway_test.py` 里加了
> 一条静态检查盯着它，避免第三次。

## 0. 一句话结论

**控制面零缺口**（MCP 18 个工具全在，只差 App 端一个 header）；**数据面**用"插件"补齐 —— 但插件**不能挂进 AzurPilot 进程**，因为更新器会把它静默抹掉。所以插件是一个**独立进程 + 同域路径转发**。

## 3. 四条关键约束（决定了架构）

### 3.1 改 AzurPilot 的跟踪文件 = 静默回退 ❌

`deploy/Windows/git.py:162`：

```python
self.execute(f'{git} reset --hard {source}/{branch}')
```

- 更新路径（`deploy/Windows/git.py`、`deploy/git.py`、`deploy/git_over_cdn/client.py`）**没有任何 `git clean`**（已全查，零匹配）
- 结论：**跟踪文件的修改会被无声抹掉**（不是冲突、不报错）；**未跟踪文件安全存活**

**派生结论：**
- ❌ 不能改 `module/webui/app.py:404`（`application.mount("/mcp", mcp_app)`）
- ❌ 不能改 `module/webui/api.py:1785`（`api_routes`）
- ❌ 不能改 `gui.py:236`（`uvicorn.Config("module.webui.app:app", ...)`）
- ✅ 新增未跟踪文件安全；`.gitignore:19` 里 `/toolkit` 已被忽略，是天然落点

> 另一条死路：把补丁**提交**到本地 git。`updater.py:128-135` 会发现"上游没有的本地提交"并**永久跳过更新** —— 等于版本冻结。

### 3.2 App 发不出凭据（当前代码）

| 通道 | 位置 | 带了什么 |
|---|---|---|
| MCP SSE | `McpClient.kt:58-62` | 只有 `Accept` |
| MCP POST | `McpClient.kt` `post()` | 只有 `Content-Type` |
| 纯 HTTP | `McpClient.kt:1250` `httpGet()` | 无任何 header |

### 3.3 但 MCP 只有**一个**请求需要凭据 ✅

`module/webui/mcp_auth.py:296-332`：

```python
if check(extract_credential(headers, query_string)):
    return True, None                                   # 带对凭据 → 放行
if route == "/messages" and is_authorized_session(
        extract_session_id(query_string)):
    return True, None                                   # ← POST 靠 session_id 继承
return False, 401
```

`session_id` 由服务端**只经已鉴权的 SSE 流**下发 → **后续所有 POST 自动继承授权**。
→ App 端**只需在 SSE 那个 GET 上加一个 header**。

另：`mcp_auth.py:320-322` 保证**未配置密码时全放行** —— 天然的向后兼容。

### 3.4 桥必须保持纯标准库

`mobile_bridge.py:62-77` 只 import 标准库（`csv/io/json/math/os/re/socket/sqlite3/subprocess/sys/threading/time/datetime/http.server/pathlib/urllib.parse`）—— 因为它要打包成 `AzurRemBridge.exe`。

> 文件内注释印证：`/api/ship_exp` 原先 `import module.statistics.ship_exp_stats`，打包成 exe 后没有项目 venv，import 必失败，于是复刻成了只读移植版。

→ **插件不能 `import module.webui.mcp_auth`**，鉴权要自带实现（`secrets.compare_digest` + 极简 yaml 取值）。

## 4. 架构

### 4.1 拓扑

```
公网（Cloudflare，dashboard 托管）
  example.com/           → localhost:25548   WebUI
  example.com/mcp/*      → localhost:25548   MCP（自带 Bearer 鉴权）
  example.com/api/*      → localhost:25548   只读 HTTP（ap_timeline / cl1_stats）
  example.com/plugin/*   → localhost:25550   插件  ← ★新增一条 Public Hostname

内网（直连）
  http://<IP>:25548/...             AzurPilot
  http://<IP>:25550/api/...         插件（无前缀）
  http://<IP>:25550/plugin/api/...  插件（带前缀，等价）
```

**为什么插件是独立进程而不是真·挂在 ASGI 里**：见 §3.1 —— 挂进去需要改跟踪文件，`git reset --hard` 会静默抹掉。

**为什么仍然算"转发到 web 端"**：同一个域名、同一条隧道、同一个 TLS 证书。App 视角是"这个站的一个路径"，不是"另一台服务器"。

### 4.2 App 侧配置矩阵

| 网络 | 服务器地址 | 数据桥地址 | WebUI 密码 |
|---|---|---|---|
| **内网** | `http://<IP>:25548` | **留空**（自动推导 `:25550`） | 填 |
| **公网** | `https://example.com` | `https://example.com/plugin` | 填 |

- 内网留空的依据：`Settings.kt:59-65` `effectiveBridgeUrl` → `http://$host:25550`；`AppViewModel.kt:553-557` 把它排进候选
- 公网必须手填：推导只能给出 `http://example.com:25550`，而 **CF 不代理 25550**
- 路径前缀能保住：`McpClient.kt:458-459` 的 `orderCandidates` 只做 `trimEnd('/')`，`McpClient.kt:730` 是 `httpGet("$base$path")` 字符串拼接

**→ 内网零额外配置，公网只多填一个字段。**

### 4.3 插件必须同时接受两种前缀

内网推导出的地址**不带** `/plugin`，公网手填的**带**。所以路由表注册两份：

```
/api/task_tree              ← 内网
/plugin/api/task_tree       ← 公网
```

实现上就是前缀列表循环，不是两套代码。

## 5. 组件设计

### 5.1 A：App 端凭据支持

| 项 | 改动 |
|---|---|
| `Settings.kt` | 新增 `webuiPassword` 字段（SharedPreferences，与现有字段同风格） |
| 设置页 UI | 新增密码输入框（`InputType.Password`，可切换明文） |
| `McpClient.kt:58-62` | SSE 请求加 `.header("Authorization", "Bearer $key")` |
| `McpClient.kt:1250` `httpGet()` | 同样带上（防御性；`/api/*` 现在不要，将来未必） |
| 空密码 | 不带 header —— 兼容未设密码的实例（§3.3） |

**只改一个请求就能让操控全通**（§3.3）。这是整个方案里性价比最高的一步。

### 5.2 B：插件（`mobile_bridge.py` 升级）

**不重写**。复用已有的 9 条 `ROUTES`（`mobile_bridge.py:1971-2002`）和全部 `query_*` 逻辑 —— 那些是跟 AzurPilot 原实现做过逐字段 parity 校验的（`verify_commission_parity.py`、`verify_ship_exp_parity.py`）。只加外壳：

| 改动 | 位置 | 说明 |
|---|---|---|
| ① 鉴权 | `Handler` | `Authorization: Bearer` / `X-API-Key` / `?key=`，`secrets.compare_digest` |
| ② 去 CORS | `mobile_bridge.py:2013` | 删掉 `Access-Control-Allow-Origin: *` |
| ③ 双前缀 | `ROUTES` 分发 | `/api/*` 与 `/plugin/api/*` 都认 |
| ④ 端口 | `mobile_bridge.py:129` | **保持 25550**（内网零配置的关键） |
| ⑤ 绑定 | 同上 | 保持 `0.0.0.0`（内网要用）→ **鉴权成为唯一防线** |
| ⑥ 仅 GET | `Handler` | 非 GET 一律 405 |

**密码来源**（优先级，全部纯标准库）：
1. `<root>/config/deploy.yaml` → `Password:` 行（正则取值，去引号）
2. `<root>/password.txt`（公网无密码时 AzurPilot 自动生成的兜底）
3. 都没有 → 若绑定了 `0.0.0.0`，**整体拒绝**（对齐 `mcp_auth.deny_all()` 的策略）

**每次请求按 mtime 重新取**，避免 WebUI 重启后密码变更导致插件钥匙作废。

> 已实测：`deploy.yaml` 里的密码对 MCP 有效（本机和公网都验过），所以插件读它是可靠的。

### 5.3 C：隧道（Cloudflare 控制台）

新增一条 **Public Hostname**：

| 字段 | 值 |
|---|---|
| Subdomain | （空） |
| Domain | `example.com` |
| **Path** | `/plugin` |
| Service | `http://localhost:25550` |

> 因为是 dashboard 托管（§2），**没有本地 config.yml 可改**，只能在 Zero Trust 控制台点。改完立即生效，不用重启服务。

## 6. 安全设计

| 面 | 措施 |
|---|---|
| 插件鉴权 | 复用 WebUI 密码，一把钥匙；未配密码 + 公网绑定 → 拒绝 |
| 只读 | 路由表白名单，非 GET 一律 405 |
| CORS | 删 `*`（App 是原生客户端，不需要 CORS） |
| 绑定 | 保持 `0.0.0.0` 换内网可用性，靠鉴权兜底 —— **这是本方案最大的风险接受项** |
| 日志 | 请求行里的 `?key=` 脱敏（可复用 `mcp_auth.redact()` 的正则思路） |
| Cloudflare Access | ⚠️ **不能启用** —— App 无法完成浏览器交互登录，套上 `/mcp/*` 或 `/api/*` 会连操控一起废掉。鉴权交给 MCP 与插件各自的密码层 |

## 7. 降级行为

| 场景 | 表现 |
|---|---|
| 密码错 / 未填 | MCP 401 → 主页/任务/配置报"无法连接"；插件 401 → 统计页不可用。两者独立，互不拖累 |
| 插件不可达（隧道抖 / 未启动） | 仅 Tier 2 五个统计页降级，Tier 1 与操控不受影响 |
| 实例未运行 | 沿用现有逻辑（README：运行中为空，逾期任务留在队列中） |

**Tier 归属**（决定降级粒度）：

- **Tier 1**（MCP + `/api/*`，免插件）：状态 · 资源 · 当前任务 · 调度队列 · 日志 · 配置读写 · 任务列表 · 截图 · 行动力曲线 · 侵蚀1月度 · **全部操控**
- **Tier 2**（插件）：资源趋势 · 委托收益 · 耄耋相接 · 每日经验 · 配置树中文名 · 队列中文名

## 8. 未决 / 风险

| # | 项 | 说明 |
|---|---|---|
| 1 | 公网需手填一个字段 | 无法做到"绝对零配置"（`effectiveBridgeUrl` 写死 `:25550`）。要消除得改 App 推导逻辑 |
| 2 | 插件绑 `0.0.0.0` | 内网可用性的代价。若不信任局域网，可改绑 `127.0.0.1`，但内网就得走隧道 |
| 3 | 密码源三处 | `deploy.yaml` / `-k` 启动参数 / `password.txt`。目前已验证第 1 种有效；另两种需兜住 |
| 4 | 统计口径漂移 | Tier 2 的数字是**复刻** AzurPilot 的（`commission_stats.py`、船经验只读移植版）。上游改口径就会不一致，靠 parity 脚本发现 |
| 5 | 隧道抖动 | 实测出现过 502。插件调用需要超时 + 重试，不能挂死 |
| 6 | 暴力破解 | 插件暴露在公网，无限速。可后续加 Cloudflare Rate Limiting 规则 |

## 9. 建议实施顺序

1. **App 端凭据支持** —— 单独就能让公网/内网的**操控 + Tier 1** 全部跑通，可独立验证
2. **插件外壳**（鉴权 + 去 CORS + 双前缀 + 仅 GET）—— 内网先验
3. **Cloudflare Public Hostname** 加 `/plugin`
4. **端到端验证矩阵**：{内网, 公网} × {操控, Tier 1, Tier 2} × {密码对, 密码错}
